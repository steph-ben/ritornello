# App installable hors ligne (PWA) : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Ritornello s'installe depuis Chrome Android (icône, fenêtre plein
écran) et s'ouvre sans réseau.

**Architecture :** un manifeste (`manifest.webmanifest`), deux icônes PNG
tirées d'une icône SVG, et un service worker (`sw.js`) qui garde une copie
des fichiers de l'app. Stratégie « réseau d'abord » : en ligne, on prend
toujours la dernière version (pas de version à incrémenter à la main), et
hors ligne, la copie.

**Tech Stack :** Web App Manifest, Service Worker, Cache API.

**Spec :** `docs/superpowers/specs/2026-11-10-ritornello-design.md`

## Global Constraints

- Installable sur Android depuis Chrome : manifeste avec `name`,
  `start_url`, `display: standalone`, des icônes 192 et 512 px, et un
  service worker avec un gestionnaire `fetch`.
- Marche hors ligne : l'app s'ouvre sans réseau. La musique vient des
  fichiers du téléphone (handles), donc rien à mettre en cache pour elle.
- Thème sombre : `background_color` et `theme_color` à `#15161a`.
- Pas de copie de la musique dans le cache : le service worker ne garde
  que les fichiers de l'app.

## Décisions prises dans ce plan

- Réseau d'abord plutôt que cache d'abord : un peu plus lent sur un réseau
  faible, mais on ne voit jamais une vieille version. Il n'y a pas de numéro
  de version à penser à changer.
- L'icône : un carré sombre arrondi avec une flèche de boucle couleur
  ambre (`#e0a458`), comme le bouton « ⟲ Boucle ». Une seule icône, aussi
  déclarée `maskable` (le dessin reste dans la zone centrale de 80 %).

## Review Focus

1. Ouvrir l'app sans réseau, après une première visite : l'écran s'affiche
   et les listes sont là. Essai headless, serveur arrêté (tâche 2).
2. Publier une nouvelle version : elle est servie à la visite suivante, en
   ligne. Garanti par « réseau d'abord ». Essai headless (tâche 2).
3. Requêtes vers un autre site (plus tard l'API GitHub pour le gist) : le
   service worker ne les touche pas. Revue du code (tâche 2).

### Task 1: manifeste et icônes

**Files :** create `manifest.webmanifest`, `icons/icon.svg`,
`icons/icon-192.png`, `icons/icon-512.png`. Modify `index.html` (lien vers
le manifeste, `theme-color`, icône).

- [ ] Dessiner `icons/icon.svg`, puis produire les PNG avec Brave headless
  (`--screenshot`, `--window-size=512,512`, puis 192).
- [ ] Écrire le manifeste : `name` « Ritornello », `short_name`
  « Ritornello », `start_url` « ./ », `scope` « ./ », `display`
  « standalone », les couleurs, et les icônes (`purpose: "any maskable"`).
- [ ] Vérifier : le manifeste est du JSON valide, et les PNG font bien
  192×192 et 512×512.
- [ ] Commit.

### Task 2: service worker

**Files :** create `sw.js`. Modify `app.js` (enregistrement).

- [ ] Écrire `sw.js` : à l'installation, mettre en cache la liste des
  fichiers de l'app. `fetch` : seulement les requêtes GET du même site.
  Réseau d'abord, la réponse fraîche remplace la copie, et si le réseau
  échoue, on sert la copie. À l'activation, `clients.claim()`.
- [ ] Dans `app.js` : `navigator.serviceWorker.register('sw.js')` si
  disponible, sans bloquer le reste.
- [ ] Essai headless : première visite (le cache se remplit), puis serveur
  arrêté et page rechargée : l'écran s'affiche. Ensuite, un fichier modifié
  sur le serveur est bien servi à la visite suivante.
- [ ] Commit.
