# Lecteur Ritornello : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un écran qui ouvre un fichier audio, le lit, le transpose, change sa
vitesse et boucle entre deux marqueurs, sur le modèle du mode Boucle de
Transpose.

**Architecture :** une page statique à la racine du dépôt, servie par GitHub
Pages. Pas de framework ni de build : modules ES chargés par le navigateur. La
logique pure (marqueurs, boucle, bornes, formats, forme d'onde) est dans des
modules sans accès au navigateur, testés avec `node --test`. Tout le code audio
est dans un seul fichier, `player.js`, pour pouvoir remplacer SoundTouchJS par
Rubber Band sans toucher au reste.

**Tech Stack :** HTML, CSS, JavaScript (modules ES), Web Audio, SoundTouchJS
0.3.0 (copie locale), File System Access API, Wake Lock API, `node --test`
(Node 22, aucune dépendance npm).

**Spec :** `docs/superpowers/specs/2026-11-10-ritornello-design.md`

Ce plan est le premier d'une série. Hors de ce plan : les listes de morceaux et
la mémorisation des fichiers (IndexedDB), la PWA (manifeste, service worker),
la synchronisation par gist, YouTube.

## Global Constraints

- Jamais de copie de la musique : le fichier est lu en mémoire, rien n'est
  écrit nulle part.
- `showOpenFilePicker()` est appelé **sans** filtre de type (`types`) : sinon
  Proton Drive grise tous les fichiers.
- Formats : au minimum `.mp3` et `.aac`, décodés avec `decodeAudioData`.
- Pas de lecture en arrière-plan : l'écran reste allumé pendant la lecture
  (Wake Lock).
- Code lisible par un humain sans IA : peu de fichiers, pas de framework,
  noms explicites. Identifiants en anglais, textes de l'interface en français.
- Thème sombre par défaut.
- Navigateurs visés : Chrome Android, Brave (flag
  `file-system-access-api` activé). Safari et Firefox n'ont pas
  `showOpenFilePicker` : afficher un message, ne pas planter.
- Pas de bouton A-B : la boucle se fait toujours entre deux marqueurs.

## Décisions prises dans ce plan

- Vitesse : de 25 % à 200 %, par pas de 5 %. Transposition : de −12 à +12
  demi-tons, par pas de 1.
- Recul et avance : 5 secondes.
- Un marqueur a un `id` stable. Son numéro affiché est sa position dans
  l'ordre du temps (1, 2, 3…), donc il change si on insère un marqueur plus
  tôt. La boucle référence les `id`, pas les numéros.
- Nom par défaut : `marker <id>`.
- Pendant une boucle active, dès que la lecture atteint ou dépasse la fin de
  la boucle, elle repart au début de la boucle. Cela vaut aussi si on
  déplace la lecture après la fin de la boucle.
- La barre de temps (marqueurs numérotés et zone de boucle) et la forme
  d'onde sont dessinées dans un seul `<canvas>` : une bande de 24 px en haut
  pour la barre de temps, la forme d'onde en dessous.

## Review Focus

1. Supprimer un marqueur de la boucle active : la boucle se coupe, le badge
   disparaît, pas d'erreur. Test : `loopBounds returns null when a marker is
   missing` (tâche 1).
2. Boucle entre un marqueur et lui-même, ou entre deux marqueurs au même
   instant : la boucle est refusée (null), pas de saut en continu. Test :
   `loopBounds returns null for an empty loop` (tâche 1).
3. Fichier que le navigateur ne sait pas décoder (un `.aac` sur Android, par
   exemple) : message visible avec le nom du fichier, le lecteur reste
   utilisable. Vérification manuelle (tâche 3, étape 4).
4. Ouvrir un second fichier pendant la lecture : le premier s'arrête, on
   n'entend jamais deux sons en même temps. Vérification manuelle (tâche 3,
   étape 4).
5. Fichier très long (enregistrement d'une heure) : la forme d'onde se
   calcule sans bloquer la page plus d'une seconde. Test : `computePeaks
   handles one hour of audio quickly` (tâche 2).

### Tâche 1 : logique d'un morceau (`track.js`)

**Files :**
- Create : `track.js`
- Test : `tests/track.test.js`

**Interfaces :**
- Produces (toutes des fonctions pures, qui ne modifient pas leurs
  arguments) :
  - `type Marker = { id: number, time: number, name: string }`. Le tableau
    `markers` est toujours trié par `time`.
  - `addMarker(markers: Marker[], time: number) -> Marker[]`
  - `removeMarker(markers: Marker[], id: number) -> Marker[]`
  - `renameMarker(markers: Marker[], id: number, name: string) -> Marker[]`
  - `markerNumber(markers: Marker[], id: number) -> number`, base 1
  - `loopBounds(markers: Marker[], loop: {fromId, toId} | null) -> {start, end} | null`
  - `positionAfterTick(time: number, bounds: {start, end} | null) -> number | null`,
    qui renvoie le temps où sauter, ou `null` s'il n'y a pas de saut
  - `stepSpeed(percent: number, direction: -1 | 1) -> number`
  - `stepSemitones(semitones: number, direction: -1 | 1) -> number`
  - `formatTime(seconds: number) -> string`

- [ ] **Étape 1 : écrire les tests qui échouent**

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { addMarker, removeMarker, renameMarker, markerNumber, loopBounds,
  positionAfterTick, stepSpeed, stepSemitones, formatTime } from '../track.js';

test('addMarker keeps markers sorted by time with stable ids', () => {
  let m = addMarker([], 30);
  m = addMarker(m, 10);
  assert.deepEqual(m, [
    { id: 2, time: 10, name: 'marker 2' },
    { id: 1, time: 30, name: 'marker 1' },
  ]);
  assert.equal(markerNumber(m, 1), 2);
});

test('addMarker does not modify its argument', () => {
  const m = addMarker([], 5);
  addMarker(m, 7);
  assert.equal(m.length, 1);
});

test('removeMarker and renameMarker', () => {
  const m = addMarker(addMarker([], 1), 2);
  assert.deepEqual(removeMarker(m, 1).map(x => x.id), [2]);
  assert.equal(renameMarker(m, 2, 'refrain')[1].name, 'refrain');
});

test('loopBounds orders the two markers', () => {
  const m = addMarker(addMarker([], 51), 11);   // id 1 à 51 s, id 2 à 11 s
  assert.deepEqual(loopBounds(m, { fromId: 1, toId: 2 }), { start: 11, end: 51 });
});

test('loopBounds returns null when a marker is missing', () => {
  const m = addMarker([], 11);
  assert.equal(loopBounds(m, { fromId: 1, toId: 99 }), null);
  assert.equal(loopBounds(m, null), null);
});

test('loopBounds returns null for an empty loop', () => {
  const m = addMarker(addMarker([], 11), 11);
  assert.equal(loopBounds(m, { fromId: 1, toId: 1 }), null);
  assert.equal(loopBounds(m, { fromId: 1, toId: 2 }), null);
});

test('positionAfterTick jumps back at or after the loop end', () => {
  const b = { start: 11, end: 51 };
  assert.equal(positionAfterTick(30, b), null);
  assert.equal(positionAfterTick(51, b), 11);
  assert.equal(positionAfterTick(80, b), 11);
  assert.equal(positionAfterTick(80, null), null);
});

test('stepSpeed moves by 5 between 25 and 200', () => {
  assert.equal(stepSpeed(100, -1), 95);
  assert.equal(stepSpeed(25, -1), 25);
  assert.equal(stepSpeed(200, 1), 200);
});

test('stepSemitones moves by 1 between -12 and 12', () => {
  assert.equal(stepSemitones(0, 1), 1);
  assert.equal(stepSemitones(-12, -1), -12);
  assert.equal(stepSemitones(12, 1), 12);
});

test('formatTime gives mm:ss', () => {
  assert.equal(formatTime(0), '00:00');
  assert.equal(formatTime(14.9), '00:14');
  assert.equal(formatTime(292), '04:52');
  assert.equal(formatTime(3725), '62:05');
});
```

### Tâche 2 : forme d'onde (`waveform.js`)

**Files :**
- Create : `waveform.js`
- Test : `tests/waveform.test.js`

**Interfaces :**
- Consumes : `Marker`, `markerNumber` (tâche 1).
- Produces :
  - `computePeaks(samples: Float32Array, count: number) -> Float32Array`, de
    longueur `count`. Chaque valeur est le maximum de `|échantillon|` dans sa
    tranche, entre 0 et 1.
  - `drawTimeline(canvas, { peaks, duration, currentTime, markers, bounds })`,
    qui dessine la bande de temps (24 px), les marqueurs numérotés, la zone
    de boucle surlignée (si `bounds` n'est pas null), la forme d'onde et la
    tête de lecture.
  - `timeAtX(canvas, x: number, duration: number) -> number`, qui convertit
    une position touchée en secondes, bornée entre 0 et `duration`.

- [ ] **Étape 1 : écrire les tests qui échouent**

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { computePeaks } from '../waveform.js';

test('computePeaks takes the max absolute value per slice', () => {
  const s = new Float32Array([0.1, -0.8, 0.3, 0.2, -0.1, 0.05]);
  assert.deepEqual(Array.from(computePeaks(s, 2)).map(v => +v.toFixed(2)), [0.8, 0.2]);
});

test('computePeaks handles fewer samples than peaks', () => {
  assert.equal(computePeaks(new Float32Array([0.5]), 4).length, 4);
});

test('computePeaks handles one hour of audio quickly', () => {
  const s = new Float32Array(44100 * 3600);
  const t0 = performance.now();
  computePeaks(s, 2000);
  assert.ok(performance.now() - t0 < 1000);
});
```

### Tâche 3 : lecture audio (`player.js`) et écran minimal

**Files :**
- Create : `vendor/soundtouch.js`, une copie de `dist/soundtouch.js` du
  paquet `soundtouchjs@0.3.0` (`npm pack soundtouchjs@0.3.0`, dans un
  dossier temporaire, pas dans le dépôt)
- Create : `vendor/soundtouch-LICENSE`, copié depuis `LICENSE` du même paquet
- Create : `player.js`, `index.html`, `style.css`, `app.js`

**Interfaces :**
- Produces (`player.js`, état gardé dans le module) :
  - `loadAudio(arrayBuffer: ArrayBuffer) -> Promise<{ duration: number, samples: Float32Array }>`,
    qui arrête et remplace le morceau en cours et réapplique la vitesse et
    la transposition. `samples` est le canal 0.
  - `play()`, `pause()`, `isPlaying() -> boolean`
  - `seek(seconds: number)`
  - `setSpeed(percent: number)`, `setSemitones(semitones: number)`
  - `onTimeUpdate(callback: (seconds: number) -> void)`
  - `onEnded(callback: () -> void)`
- Pièges de l'API SoundTouchJS 0.3.0 (lus dans le code source) :
  - `new PitchShifter(audioContext, audioBuffer, 4096, onEnd)`.
  - Lecture : `shifter.connect(gainNode)`. Pause : `shifter.disconnect()`.
  - Se déplacer : `shifter.percentagePlayed = fraction`. Le setter attend
    une **fraction entre 0 et 1**, alors que le getter renvoie 0–100.
  - `shifter.tempo = percent / 100`, `shifter.pitchSemitones = n`.
  - L'événement `'play'` (`shifter.on('play', d => d.timePlayed)`) donne le
    temps joué, en secondes du fichier.
  - `shifter.off()` ne retire pas vraiment les écouteurs (bug de la
    bibliothèque). Donc, au changement de morceau, on crée un nouveau
    `PitchShifter` et on ignore les événements de l'ancien (comparer à la
    référence courante).
- L'`AudioContext` est créé ou repris (`resume()`) dans le geste de
  l'utilisateur (clic sur « Ouvrir » ou sur lecture).

### Tâche 4 : l'écran complet du lecteur

**Files :**
- Modify : `index.html`, `style.css`, `app.js`

**Interfaces :**
- Consumes : tout ce que produisent les tâches 1, 2 et 3.
- État dans `app.js` : `markers: Marker[]`, `loop: {fromId, toId} | null`,
  `loopActive: boolean`, `speed: number` (100), `semitones: number` (0),
  `peaks`, `duration`.

Ordre de l'écran, de haut en bas, comme dans la spec :
1. Transposition `− 0 +` et vitesse `− 100 % +`.
2. Le compteur, qui affiche aussi la boucle en cours : `00:11 ⇄ 00:51`.
3. Le canvas (`drawTimeline`). Un toucher appelle `seek(timeAtX(...))`.
4. Le bouton « + Marker », puis la liste des marqueurs : numéro, temps, nom
   modifiable (`<input>`), bouton de suppression.
5. Le choix de la boucle : deux `<select>` de marqueurs (par numéro), un
   bouton boucle (active/coupe), et le badge `1–3` quand la boucle est
   active.
6. En bas : début, −5 s, lecture/pause, +5 s, et `00:14 / 04:52`.

Comportement :
- À chaque `onTimeUpdate` : redessiner, mettre à jour les temps, et si la
  boucle est active, `positionAfterTick(t, loopBounds(markers, loop))`.
  Si le résultat n'est pas null, `seek` vers ce temps.
- Si `loopBounds` renvoie null (marqueur supprimé, boucle vide), couper la
  boucle (`loopActive = false`) et masquer le badge.
- `onEnded` : pause, retour à 0.
- Wake Lock : `navigator.wakeLock.request('screen')` à la lecture,
  `release()` à la pause. Le redemander sur `visibilitychange` si la
  lecture est en cours. Si l'API manque, continuer sans message.
- Ouvrir un nouveau morceau remet à zéro les marqueurs et la boucle (la
  mémorisation par morceau viendra avec le plan des listes).
